2. Defect register (bug taxonomy applied)

CAT-SEC-001 — No session guard: every buyer page is served to anonymous visitors

Security · severity S1 · priority P1 · status Open

Expected: Unauthenticated requests to amazon.html, checkout.html, orders.html, user_details.html, payments.html and tracking.html are redirected to login.html.

Actual: All six pages render their full content without any login; no session token is created at login time either.

Repro: Open http://127.0.0.1:5501/checkout.html directly in a fresh browser profile.

Root cause: login.html never persists an authenticated session and no page performs an access check.

Detected by: TC-SEC-01, TC-SEC-02, TC-SEC-03, TC-SEC-04, TC-SEC-05, TC-SEC-06, TC-SEC-07

CAT-SEC-002 — Card number is written into the URL by a GET form submission

Security · severity S1 · priority P1 · status Open

Expected: Payment data is never exposed in the address bar, browser history or Referer header.

Actual: payments.html submits through GET with named inputs, producing ?card-number=4111111111111112&expiration-date=...&cvv=...

Repro: Submit a valid card on payments.html and inspect the address bar after the success alert.

Root cause: The Proceed control is a bare submit button inside a form with no method/action and no preventDefault.

Detected by: TC-PAY-12

CAT-SEC-003 — Hard-coded credentials shipped in client-side source

Security · severity S2 · priority P1 · status Open

Expected: Credential verification happens server side; no secret appears in page source.

Actual: login.html contains both valid username/password pairs in an inline script.

Repro: View source of login.html and search for the password strings.

Root cause: Authentication implemented entirely in the browser for the assignment demo.

Detected by: TC-LOGIN-10

CAT-SEC-004 — Credential policy violated: numeric-only password accepted

Security · severity S3 · priority P3 · status Open

Expected: Per REQ-09.3 the password must be at least 8 characters with mixed character classes.

Actual: The account 'Yogesh' authenticates with the 10-digit phone number 8329097855.

Repro: Log in with Yogesh / 8329097855.

Root cause: No password policy is enforced anywhere in the application.

Detected by: TC-SEC-08

CAT-VAL-003 — Expiry date validation accepts impossible and past dates

Validation · severity S2 · priority P2 · status Open

Expected: Months 01-12 only, and any date earlier than the current month must be refused.

Actual: The expression /^\d{2}\/\d{2}$/ accepts 13/25, 99/99 and 01/20.

Repro: Enter expiry 13/25 (or 99/99, or 01/20) with a valid card and CVV, then press Proceed.

Root cause: isValidExpirationDate in payments.html only checks the shape of the string.

Detected by: TC-PAY-06, TC-PAY-07, TC-PAY-08

CAT-VAL-005 — Login failure message blames the wrong field

Validation · severity S3 · priority P3 · status Open

Expected: An unknown username must be reported as a username problem.

Actual: An unknown username with the password '5555' is reported as 'Invalid Password'.

Repro: Submit username 'nobody' with password '5555'.

Root cause: login.html tests the password branch before the username branch.

Detected by: TC-LOGIN-05

CAT-VAL-013 — Zipcode accepts any character and any length

Validation · severity S3 · priority P3 · status Open

CAT-VAL-014 — Card number accepts any 16 digits (no checksum)

Validation · severity S3 · priority P3 · status Open

Expected: A card that fails the Luhn checksum is refused.

Actual: 0000000000000000 is accepted as a successful payment.

Repro: Pay with card 0000000000000000, expiry 12/28, CVV 123.

Root cause: isValidCardNumber in payments.html only tests /^\d{16}$/.

Detected by: TC-PAY-05

CAT-NAV-002 — Hard-coded host and port in an onclick handler

Navigation · severity S2 · priority P2 · status Open

Actual: orders.html line 176 navigates to http://127.0.0.1:5501/user_details.html.

Repro: Serve the app on any port other than 5501 and press 'Buy it again' on the third order.

Root cause: Absolute URL literal inside the inline onclick attribute.

Detected by: TC-NAV-09

CAT-FUN-017 — Catalogue header cart counter is not synchronised on page load

Functional · severity S3 · priority P3 · status Open

Expected: Opening amazon.html with items already in the cart shows the live unit count in the header counter.

Repro: Seed the cart with 3 units in localStorage, open amazon.html, and read the header counter before clicking anything.

Root cause: scripts/amazon.js calls updateCartQuantity() only inside the add-to-cart click handler (line 80) and never on initial render, while amazon.html hard-codes .js-cart-quantity to 0.
